1 · COMMANDING BASICS

What C&DH Does

How electronics exchange information

Responsibilities
  • Receive, validate and route commands
  • Collect and time-stamp telemetry
  • Store data until the next pass
  • Keep spacecraft time
  • Detect faults and recover (safe mode)
Today: Spacecrafts are a collection of subsystems; how do they communicate between each other

Place C&DH in the system. the OBC is the hub; everything else hangs off one or more buses.

1 · COMMANDING BASICS

Binary: 1s and 0s

Before any data: how electronics represent information

Vocabulary

Bit: one 1 or 0, a voltage high or low on a wire

Byte: 8 bits → 256 values (0–255)

Hex: shorthand, 4 bits per digit: 0100 1011 = 0x4B

Meaning:

  • 0x4B is 75,
  • or the letter K,
  • or the raw/uncalibrated temperature from an ADC (Analog to Digital Converter)
Every protocol today answers one question: how do two systems agree where the bits are and what they mean?

For students who have never thought about signals. A wire is either high or low; everything else is convention.

1 · COMMANDING BASICS

Open Loop vs Closed Loop

Basic commanding architecture

Open Loop

Gain: simplest; works on one-way links; no reverse traffic

Cost: no feedback; a dropped package is silent; verify later in telemetry

Closed Loop

Gain: sender knows it arrived; retries recover losses

Cost: reverse channel, timers, state; a lost ACK looks like a lost command

ACK means received, not executed. Verify execution in telemetry (e.g., acceptance → start → completion).

Fire-and-forget is not wrong: time broadcasts and one-way links use it. The point is where verification happens.

Example, firmware upload:

PADRE (open loop): the whole image is uploaded in one go; the transfer takes under a second; it is verified afterwards.

COSI (closed loop): the image is chopped into small sections. Each write is commanded from the ground, the instrument answers, and only then does the next section go up. One round trip per section, so a full image takes hours.

Point: closed loop buys certainty per chunk; you pay one round-trip latency per chunk.

1 · COMMANDING BASICS

Links, Buses and Addresses

Who are you talking to? One receiver or many: the topology decides whether you need an address.

Point-to-point
  • No address needed
  • One link per device: more harness
  • e.g., UART / RS-422, SpaceWire link
Shared bus
  • Every node hears everything
  • Address selects the receiver
  • e.g., I2C, RS-485, CAN, MIL-STD-1553
Addressing modes

Unicast: one node, by address

Broadcast: all nodes at once (e.g., time sync); nobody can ACK

Node addressing: the frame says who it is for (“to node 0x21”). Only that node accepts it.

Message addressing: the frame says what it is (“battery voltage”). Every node that needs it reads it; the sender does not know who listens.

Every node on a bus must reject traffic that is not addressed to it, in hardware or in software.

Node addressing (I2C, 1553) vs message addressing (CAN) is a useful distinction for later.

1 · COMMANDING BASICS

Polled vs Streaming

Knob: who decides when data moves?

Polled: request when ready

Gain: receiver is never overrun; deterministic bus schedule

Cost: latency; request traffic; sender must buffer between polls

e.g., I2C, SPI, 1553, USB

Streaming: send when you can

Gain: lowest latency, full link throughput, simple sender

Cost: receiver must always be ready; a busy receiver drops data silently

e.g., UART payload streams, video

Example on PADRE: SHARP and MeDDEA

Polled protects the receiver; streaming protects throughput. BTO was a streaming link.

What a Receiver Needs to Know

Every header field answers one question.

Header + trailer = overhead: bytes that carry no science but make the science usable.

A receiver that does not have all the information in the header will eventually process the wrong bytes.

Walk left to right. Ask: what goes wrong if this field is missing? That sets up CCSDS and the BTO case.

2 · OVERHEAD

CCSDS Space Packet: The Standard Answer

CCSDS 133.0-B: a 6-byte primary header used by most science missions

APID: which application or instrument the packet belongs to; receivers filter on it

Seq count: per-APID counter, wraps at 16 383

Packet data length: data-field bytes − 1

Type: telemetry (0) or telecommand (1)

67 %4-byte command → 12 bytes on the wire
< 1 %1000-byte packet → 1008 bytes
Overhead hurts short commands, not bulk data. Trading away the header to save bytes on a command link is possible, but carries significant risk

Field widths: version 3, type 1, secondary header flag 1, APID 11, sequence flags 2, sequence count 14, packet data length 16 bits. Length field is data-field octets minus one.

2 · OVERHEAD

Sequence Count: What It Tells You

A 14-bit counter per APID. Four patterns worth recognising.

Count per APID and log every anomaly. It is the cheapest diagnostic you will ever fly (see the BTO case).

The sequence count is free diagnostics. Most anomaly investigations start by plotting it.

2 · OVERHEAD

Checksum vs CRC

Both sides agree on the method beforehand. The sender appends the result; the receiver recomputes and compares.

Checksum: add the bytes
dataresult
12 340x46original
34 120x46bytes swapped: missed
13 330x46+1 / −1 cancel: missed

Cheap, but blind to byte order and to errors that cancel out.

CRC: divide by an agreed generator
dataresult
12 340x0EC9original
34 120xE62Dbytes swapped: caught
13 330x4D1F+1 / −1 cancel: caught

Every bit passes through the division, so position matters.

CRC-16-CCITT (generator 0x1021) catches every burst of up to 16 bits.

Both ends must agree on the generator and start value before launch. A mismatch rejects every packet.

Same three payloads in both columns. The checksum gives 0x46 every time. The CRC is a division by an agreed generator (no carries, XOR); the remainder is the CRC. Because every bit passes through the division, order and position change the result.

Section 3: Protocols

From bytes to wires

3 · PROTOCOLS

Single-Ended vs Differential Signalling

Shared ground on one wire vs floating ground on two wires r?

Single-ended (wire + ground)
  • Cheap, few pins; fine on one board
  • Noise and ground offset add straight to the signal
  • TTL UART, I2C, SPI, RS-232
Differential (A − B)
  • Rejects common-mode noise and ground shifts
  • Twisted pair: fields cancel, low emissions
  • Two wires per signal + transceivers
  • RS-422/485, CAN, LVDS / SpaceWire, USB
Rule of thumb: on one board, single-ended is fine. Across a harness between boxes, go differential.

Ground offset between boxes is the practical killer for single-ended links across a harness.

3 · PROTOCOLS

Who Owns the Clock?

The receiver must sample each bit in its middle. How does it know where the middle is?

Asynchronous: UART
  • Each side has its own clock at an agreed baud rate
  • Re-aligns on every start bit; clocks must match within a few %
  • No extra wire
Synchronous: SPI, I2C
  • The main sends the clock on its own wire
  • Data sampled on clock edges: any speed, can pause
  • One more wire; clock-to-data skew limits speed and cable length
Third option: embed the clock in the data by guaranteeing edges (next slide).

Single-ended vs differential was about voltage. This is about time. Show the red ticks drifting into the next bit.

3 · PROTOCOLS

Sending the Clock Inside the Data

Line coding turns bits into levels. The receiver re-aligns its clock on every edge.

Why NRZI over NRZ
  • Differential in time: the bit is the change between neighbouring levels, not the level
  • Polarity-proof: swap the two wires and NRZ inverts every bit; NRZI decodes unchanged
  • Edges guaranteed: 0s always toggle; bit stuffing breaks long runs of 1s
  • Differential signalling (two wires) is a separate idea. USB uses both
CAN: NRZ + bit stuffing. USB: NRZI + bit stuffing. MIL-STD-1553: Manchester.

NRZI is differential encoding in time. Do not confuse it with differential signalling on two wires; USB uses both.

3 · PROTOCOLS

UART: The Byte Is the Whole Protocol

Universal Asynchronous Receiver-Transmitter. 8N1: 1 start, 8 data, no parity, 1 stop bit.

No clock wire

Both ends must agree on the baud rate, within a few percent, and resynchronise on every start bit

Defines a byte, nothing more

No address, packet, ACK or CRC. Sync word, length and CRC are yours to add

UART ≠ voltage

Same logic drives TTL (on-board), RS-232 (±12 V) or RS-422/485 (differential harness).

Scale check: at 115.2 kbaud a 100 MHz processor runs ~8 700 cycles per byte. It can still miss one.

Foreshadow BTO: the processor is thousands of times faster than the line, and it can still miss a byte.

3 · PROTOCOLS

I2C: Two Wires, Many Devices

SDA = serial data, SCL = serial clock. The main drives SCL; any device may pull SDA low.

Wires: 2 (SDA, SCL) + GND

Every secondary has a fixed address, set by the part (some by pins)

How it behaves

ACK every byte: in the 9th clock the receiver pulls SDA low. No device at that address → line stays high (NACK): nobody home

Open-drain: devices only pull low; resistors pull high. That is why anyone can ACK, and why one stuck device can hang the bus

Flight risk: a device reset mid-transfer can hold SDA low and the whole bus hangs.

The address is simply who I talk to. The ACK is the receiver holding SDA low for one clock after each byte.

3 · PROTOCOLS

SPI: Fast, Simple, Unchecked

MOSI = main out, secondary in · MISO = main in, secondary out · CS = chip select

Wires: 4 (SCLK, MOSI, MISO, CS) + GND
One main, three secondaries

SCLK · MOSI · MISO shared; one CS line per secondary

Adding a device costs one more CS wire: 3 secondaries = 6 wires + GND.

Trade-offs
  • Full duplex: one bit out and one bit in on every clock edge
  • Fast: MHz to tens of MHz; the main sets the pace
  • Address = a wire: pull CS low to select a device
  • No ACK, no error check: a dead device reads as 0x00 or 0xFF. Add a CRC or read back an ID register
Common small-satellite pattern: I2C for housekeeping, SPI for memory and fast ADCs, UART / RS-422 to payloads.

Contrast with I2C: no addresses on the wire, no acknowledgements. Speed is the reward; checking is your job.

3 · PROTOCOLS

USB: Every Concept in One Bus

USB is host-polled, addressed, framed, CRC-checked and acknowledged.

Wires: 4 (D+, D−, VBUS, GND)
One transaction
Concepts from this lecture

Differential pair: D+ / D−, NRZI + bit stuffing

Address: 7 bits, picks the device (up to 127)

Endpoint: a numbered buffer inside the device. EP0 = control; EP1 IN = e.g., keyboard data to the host. Address picks the device, endpoint picks the function, like an APID

Integrity: CRC-5 on tokens, CRC-16 on data

Polled: a device never talks unless the host asks

A USB “interrupt” endpoint is not an interrupt: the host polls it at a fixed interval.

A transaction is three packets: token, data, handshake. Endpoint: address picks the device, endpoint picks the function inside it.

3 · PROTOCOLS

Buffers: Absorbing the Mismatch

Producer and consumer never run at the same time or the same rate.

Ring buffer (FIFO)
  • First in, first out; fixed array, write index chases read index
  • Full: drop the newest or overwrite the oldest. Choose deliberately
rate × worst stallminimum buffer size
115 B11.5 kB/s × 10 ms flash write
1–16 Btypical UART hardware FIFO: 87 µs–1.4 ms

The hardware FIFO alone covers microseconds to a millisecond. Anything longer needs a software buffer, or DMA.

Size for the worst stall, not the average. The average is never what breaks.

Ring buffer: fixed array, write index chases read index. Decide deliberately what happens when full.

3 · PROTOCOLS

Getting Bytes into Memory: Interrupt vs DMA

ISR (interrupt service routine): code the hardware runs the moment an event occurs, e.g., a byte arrives, pausing the main program.

Interrupt per byte

Gain: simple to write and debug

Cost: CPU handles every byte; any higher-priority work longer than the FIFO covers → overrun, byte lost

DMA

Gain: bytes reach memory regardless of CPU load; CPU handles whole blocks

Cost: needs idle-line or timeout detection to find packet ends; harder setup

Interrupt latency is a budget. If anything can block the RX path longer than the FIFO covers, you will lose bytes.

Idle-line detection: the UART flags when the line has been idle for one character time, which marks the end of a burst for DMA.

4 · RADIATION AND WATCHDOGS

Mitigation Toolbox: Prevent, Detect, Recover

COTS-based small satellites cannot avoid upsets. They are built to recover from them.

Prevent
  • Radiation-hardened or tested parts
  • Shielding (helps TID, not heavy ions)
  • Latch-up-immune processes (SOI, guard rings: next slide)
Detect and correct
  • EDAC memory (corrects 1 bit, detects 2)
  • Periodic scrubbing so errors don't accumulate
  • TMR voting in FPGAs
  • CRC on code and tables before use
Recover
  • Watchdogs
  • Current-limited power switches that cycle on latch-up
  • Redundant boot images
  • Safe mode: minimal, known-good configuration
Rad-hard costs more and lags in performance. COTS is cheaper and faster, and shifts the burden to detection and recovery.

Rad-hard parts buy prevention at the cost of price and performance. CubeSats mostly fly COTS and invest in detection and recovery.

4 · RADIATION AND WATCHDOGS

Watchdogs: The Last Line of Defence

A hardware timer that resets the processor unless healthy software keeps resetting the timer.

1
Pet from the main loop, not an ISRISR = interrupt service routine, code run on a hardware event (e.g., a timer tick). It keeps firing while the main task is hung.
2
Check health before pettingPet only if every critical task reported in this cycle.
3
Make it independentExternal watchdog, own clock; a window also catches petting too fast.
4
Layer themTask → processor → EPS power cycle → ground-command timeout.
PADRE: in-flight OBC resets recovered autonomously. Recovery time is science time.

The most common watchdog bug is kicking it from a timer interrupt: the interrupt keeps firing while the main loop is stuck.

Section 5: Case Study

BTO: one dropped byte

5 · CASE STUDY

BTO: What We Saw

Case study from integration: BTO (Background and Transient Observer), the student-built instrument on COSI

The link
  • UART on RS-422 (differential), 115.2 kbaud
  • Polling: SC requests packages, receivers replies
  • Packet: SYNC | LENGTH | payload | CRC
  • Receiver finds SYNC, then reads LENGTH bytes
  • Same CPU also writes data to flash in pages
Observed, in this order:
1
Timeout waiting for packet bytes
2
Error: data on the UART line when none was expected
3
Packet no longer processed
4
Jump in sequence count
Hint: one byte went missing. Why did it cost more than one byte?

Keep this short. Collect two or three answers from chat, then move on. Hint if quiet: what is the CPU doing besides receiving?

5 · CASE STUDY

What Happened

The processor was fast enough on average, not in the worst case.

1
Page write holds off the RX interrupt longer than one byte time (86.8 µs): UART overrun, 1 byte lost
2
Parser still expects 1 more byte for this packet: timeout
3
Next packet's bytes arrive while the parser is out of step: unexpected data, CRC fails, not processed
4
Parser resyncs on the next SYNC word: downstream sees a sequence-count jump
Root cause: byte-by-byte RX in interrupt context, competing with a long flash write. Effect: one lost byte cost whole packets.

Walk the timeline left to right. 115.2 kbaud gives 86.8 microseconds per byte; the flash page write held off the RX interrupt longer than that.

SUMMARY

Takeaways

1
Decide what an ACK means (received, accepted, executed) and make commands safe to repeat.
2
Every header field answers a question: where it starts, who it is for, how long, in order, intact.
3
Differential across harnesses; single-ended on the board.
4
Polled protects the receiver, streaming protects throughput. Streaming needs buffers sized for the worst stall.
5
Assume upsets and hangs: EDAC, watchdogs and power cycling are design requirements, not extras.
6
Sequence counts and timeouts are the cheapest diagnostics you will ever fly.

Close on the BTO point: the cheapest diagnostics, sequence counts and timeouts, are what made the bug findable.
